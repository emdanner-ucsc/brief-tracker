Open questions

Background vs results briefs
BACKGROUND briefs (per strategy, per hydroclimate) explain what went into the model run — setup, assumptions, climate forcing — and carry no results. RESULTS briefs (BASELINES, theme, scenario, sector, LOI) report tier outcomes. Both are briefs; the split is by content, not format. Strategy and hydroclimate each pair a background brief with results coverage.
Is ‘brief’ still right?
Yes. A background brief is still an authored, citable, statically-rendered reference artifact — the same mold as the results briefs, just describing inputs rather than outcomes. If a finer label is wanted, ‘background brief’ or ‘reference brief’ distinguishes it in conversation.
Brief levels
The Level 1/2/3 framework was defined for RESULTS briefs (L1 curated, L2 full-coverage generated, L3 on-the-fly export). Background briefs sit outside it; assigning them a level (or a parallel track) is an open question.
Strategy background count
All 24 served strategies get a background brief, including the 5 current-operations / baseline variants (s0020, s0011, s0021, s0024, s0023). Whether those 5 are covered by BASELINES instead of standalone background briefs is an open question.
Hydroclimate mapping (RESOLVED)
Resolved 2026-06-09 against the live /api/scenarios feed + the team's Completed Scenario Listing: API hydroclimate_id 2 = BL (historical), 3 = HC1 (cc50, Warmer and Drier I), 4 = HC2 (cc95, Warmer and Drier II). The live feed returns ONLY ids 2/3/4 (24 strategies each = 72 codes). TaiESM1 (cqlTAI, runs s0107–s0131) and EC-Earth3-Veg (cqlECV, runs s0133–s0157) are run but not served. There is NO served HC3 — the ‘HC3 = TaiESM1’ row in coeqwal_conventions.md is stale and should be corrected. Dedicated hydroclimate briefs = HC1 + HC2 (BL folds into BASELINES); +2 when the queued climates are served. See the Hydroclimates tab.
Sector count: 8 vs 9
The API and conventions list 9 sectors. The 2026-05-07 Phase 0 decision says sector briefs cover ‘eight, per the scatter-vis canonical set.’ Reconcile which is authoritative before generating sector briefs.
Scenario count: 22 vs 24
Early concept docs estimated ‘~22’ scenario fact sheets. The committed API cache holds exactly 24 served strategies (× 3 hydroclimates = 72 codes). Use 24.
LOI counts (live)
Live API location counts (2026-06-09): AG 132, CWS 124, GW 42, ENV 17, RES 8 = 323 LOIs across the 5 location-resolved sectors. Four sectors (DELTA, FW_EXP, FW_DELTA_USES, WRC) report one system-wide value and have no LOI split.
LOI brief granularity
323 individual LOI briefs is far more than the 5-brief Level-1 set. The location units also differ: AG and CWS are CalSim demand units (machine codes like ‘08N_SA1’, not public place-names), GW is water-budget areas, ENV is river sites, RES is named reservoirs. OPEN QUESTION: do AG/CWS demand units publish as individual briefs, or roll up to a coarser public geography first? This decision drives whether the LOI brief count stays near 323 or drops sharply.
Briefs vs data records
A brief is one document; it contains many result points. ‘# briefs’ (Brief inventory tab) and ‘Records’ (Data records tab) answer two different questions — keep them distinct. Background briefs contain no records.
